# 图片密码加密方案

## 核心需求

用户设置一个**密码**来加密图片，只有输入正确密码才能查看图片。

---

## 工作流程

### 上传图片时

```
用户上传图片
    ↓
输入加密密码
    ↓
客户端用密码加密图片
    ↓
上传加密后的图片到服务器
    ↓
服务器保存加密图片
```

### 查看图片时

```
用户请求查看图片
    ↓
弹出密码输入框
    ↓
用户输入密码
    ↓
客户端用密码解密图片
    ↓
显示图片给用户
```

---

## 关键问题

### 1️⃣ 密码如何加密图片？

**方案**：使用密钥派生函数将密码转换为加密密钥

```
用户密码（如："123456"）
    ↓
运行 PBKDF2 或 Argon2
    ↓
生成 AES-256 加密密钥
    ↓
用这个密钥加密图片数据
```

**示例**：
- 密码：`"my_password"` → 128位/256位加密密钥
- 图片：`image.jpg` → 加密后：`image.jpg.enc`

### 2️⃣ 密码安全吗？

**风险**：
- ❌ 弱密码容易被破解
- ❌ 相同密码不够随机

**保护方法**：
- ✅ 添加 Salt（随机盐值），每个用户/文件不同
- ✅ 使用强密钥派生函数（PBKDF2 >100,000 次迭代，或 Argon2）
- ✅ 服务器验证密码强度（长度 ≥8，含大小写数字特殊符号）

### 3️⃣ Salt 存储在哪里？

**方案**：
- Salt 不需要保密，只需要随机
- **存储位置**：
  - 方案 A：存在加密文件的前16字节
  - 方案 B：存在数据库中与文件绑定
  - 方案 C：用文件名 + 用户ID 的哈希作为 Salt

**推荐**：方案 A（简单，文件自包含）

```
加密文件结构：
[16字节 Salt][加密的图片数据]
   ↓                   ↓
 明文存储            AES-256 加密
```

### 4️⃣ 服务器需要知道密码吗？

**答案**：❌ 不需要

**工作方式**：
- 服务器只保存加密后的文件
- 密码始终在客户端处理
- 服务器从不知道真实密码
- 即使服务器被黑，也无法破解图片

**流程**：
```
客户端：密码 → 派生密钥 → 加密文件 → 上传
                                    ↓
                              服务器保存
                                    ↓
客户端：密码 → 派生密钥 → 下载后解密 ← 下载加密文件
```

## 具体方案

### 场景：图片社区网站

**需求**：用户上传私密图片，设置密码保护

#### 步骤 1：上传方式

**选项 A（推荐）：客户端加密 + 服务器存储**
1. 用户上传图片 + 输入密码
2. 浏览器 JavaScript 加密
3. 上传加密文件
4. 服务器保存（不知道密码）
5. 其他用户下载会得到加密文件
6. 需输入密码才能解密查看

**优势**：
- 服务器不知道密码
- 即使数据库被偷也没用
- 用户隐私最大化

**劣势**：
- 对服务器端没有验证（能避免吗？不能）
- 用户遗忘密码无法恢复

---

#### 步骤 2：加密细节

**文件处理流程**

```
原始图片：image.jpg (2MB)
    ↓
生成随机 Salt（16 字节）
    ↓
用户输入密码 + Salt → PBKDF2 (100,000 次迭代)
    ↓
得到 AES-256 密钥 + IV（初始化向量）
    ↓
用 AES-256-CBC 加密图片数据
    ↓
组合：10-20%
  [16字节 Salt] + [16字节 IV] + [加密的图片] + [16字节 HMAC]
    ↓
得到 image.jpg.enc 文件
    ↓
上传到服务器
```

**数据结构示例**

```
加密文件格式：
├─ 字节 0-15：   Salt（公开，用于密钥派生）
├─ 字节 16-31：  IV（公开，用于 AES）
├─ 字节 32-end-16：加密的图片数据
└─ 字节 end-16-end：HMAC（验证完整性和真实密码）
```

**好处**：
- ✅ 文件自包含，不需要单独存储 Salt/IV
- ✅ HMAC 防止密码错误时的垃圾数据
- ✅ 下载者无法验证密码正确性（隐私保护）

---

#### 步骤 3：查看流程

```
用户 A 访问用户 B 的加密图片
    ↓
浏览器显示：[输入密码] [查看] 按钮
    ↓
用户输入密码，点击查看
    ↓
JavaScript 读取文件
    ├─ 提取 Salt（字节 0-15）
    ├─ 提取 IV（字节 16-31）
    └─ 提取密文（字节 32 之后）
    ↓
用 密码 + Salt → PBKDF2 派生密钥
    ↓
用密钥 + IV 解密图片
    ↓
验证 HMAC（检查密码是否正确）
    ↓
如果正确：显示图片 ✅
如果错误：提示"密码错误" ❌
```

## 实现对比

### 方案 1：客户端 JavaScript 加密（Web）

**适用**：Web 网站

**工作方式**：
- 用户在浏览器上传
- 浏览器 JavaScript/WebAssembly 处理加密
- 上传加密后的二进制文件
- 下载时在浏览器解密

**优势**：
- ✅ 服务器负担轻
- ✅ 隐私最大化
- ✅ 易于部署

**劣势**：
- ❌ 大文件加密会卡顿（几秒-几分钟）
- ❌ 不兼容低端浏览器或旧设备
- ❌ 需要 Crypto API 支持

---

### 方案 2：客户端应用加密（桌面/移动）

**适用**：桌面应用、移动应用

**工作方式**：
- 原生应用处理加密
- 调用系统 OpenSSL/BoringSSL
- 快速加密大文件

**优势**：
- ✅ 性能最好
- ✅ 完全控制
- ✅ 离线支持

**劣势**：
- ❌ 需要安装应用
- ❌ 跨平台复杂

---

### 方案 3：服务器端加密（后端）

**不推荐**：需要服务器知道密码（安全风险）

但如果必须用...方案如下：

```
用户上传：图片 + 密码
    ↓
通过 HTTPS 发送给服务器
    ↓
服务器接收：密码 → PBKDF2 → 加密 → 存储
    ↓
用户查看：发送密码 → 服务器验证 → 解密 → 返回图片
```

**风险**：
- ❌ 服务器日志可能记录密码
- ❌ 服务器被黑，所有密码泄露
- ❌ 中间人可能截获密码

**仅在 HTTPS + 严格日志管理 + 密码从不存储时可用**

## 密码安全级别

| 密码 | 强度 | 风险 | 破解时间 |
|------|------|------|---------|
| `123456` | ⭐ | 极高 | <1秒 |
| `password` | ⭐ | 极高 | <1秒 |
| `MyPass123` | ⭐⭐⭐ | 中 | 几小时 |
| `K9@mL#pQ2!xN` | ⭐⭐⭐⭐⭐ | 低 | 几年 |
| `你好12345!@#$` | ⭐⭐⭐⭐⭐ | 低 | 几年 |

**推荐密码规则**：
- 长度：≥ 12 字符
- 包含：大小写字母 + 数字 + 特殊符号
- 不要：连续数字、常见单词、生日

## 关键参数设置

### Argon2 参数（推荐用于新项目）

```
时间成本：3 次迭代
内存成本：64 MB
并行度：4 线程
输出长度：32 字节（256 位）
```

**破解难度**：
- ✅ 弱密码（6 位数字）：需要 100 年
- ✅ 中等密码（10 位混合）：需要 10,000 年

### PBKDF2 参数（兼容旧系统）

```
迭代次数：600,000 次（OWASP 推荐）
哈希算法：SHA-256
输出长度：32 字节（256 位）
```

## 常见问题

### Q1：用户忘记密码怎么办？

**A1**：无法恢复（设计如此）

**解决**：
- 建议用户记录密码
- 选项：导出未加密的备份
- 或：重新上传新文件

### Q2：可以重设密码吗？

**A2**：不行，因为需要原始密码来验证身份

**替代方案**：
- 删除旧文件
- 用新密码重新上传

### Q3：密码会被保存在浏览器历史吗？

**A3**：可能（取决于浏览器）

**防护**：
- 使用密码管理器（如 1Password、KeePass）
- 在隐私浏览模式下操作
- 避免使用公共电脑

### Q4：可以分享加密文件吗？

**A4**：可以，对方需要密码

**方式**：
- 下载加密文件分享给对方
- 通过其他渠道告诉对方密码
- 对方用密码解密

### Q5：算法有多安全？

**A5**：如果密码足够强

- PBKDF2 + 600,000 迭代：安全
- Argon2：更安全（推荐）
- AES-256：军用级加密
- HMAC：防篡改

**与银行 ATM 等级类似**

## 总结

**最简单的实现**：

```
密码 + Salt → PBKDF2 → AES-256 密钥
                    ↓
                加密图片
                    ↓
            存储在服务器
```

**核心原则**：
- 服务器不需要知道密码
- 密钥派生使用强算法
- 每个文件独立的 Salt
- 完整性用 HMAC 验证
